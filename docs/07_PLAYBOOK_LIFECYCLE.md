## What a playbook is

A playbook is a **self-describing, versioned bundle** — a directory, not a
file:

```
playbooks/halibut_trolling_v3/
├── playbook.toml          # manifest: identity, hash, deps, safety class
├── rules.py               # pure functions: f(VesselState, targets) → Intent
├── provenance.toml        # WHY each rule exists: voice refs, evidence, confidence
├── tests/
│   ├── replay_manifest.toml   # which recorded trips this was tested against
│   └── expectations.toml      # bounds the replay must satisfy
└── evidence/
    ├── replay_report.json     # generated by the gate; immutable once sealed
    └── shadow_report.json     # agreement stats from shadow deployment
```

`rules.py` contains **pure functions only**: no I/O, no imports beyond an
allowlist (`math`, `statistics`), no unbounded loops, no state between
calls. It receives an immutable state snapshot and mission targets; it
returns an intent. Determinism is enforced structurally, not hoped for.

The docstring-justification pattern from the legacy design is kept and
upgraded: every function's docstring cites its provenance (captain
transcript id, confidence). `provenance.toml` makes this machine-readable.

## The stage-gate

```
 DRAFT → ANALYZED → REPLAYED → APPROVED → SHADOW → ACTIVE → (RETIRED)
            │          │                    │
            └─ auto ───┴── agents ──────────┘   └─ HUMAN GATE ─┘
```

### Stage 1 — DRAFT (Engineer agent)

Trigger sources: learned behavior from voice+telemetry, Analyst finding,
fleet playbook import, or direct human request. The Engineer writes
`rules.py`, `provenance.toml`, and declares expected operating envelope in
`playbook.toml`.

### Stage 2 — ANALYZED (static gate, automated)

- AST scan: import allowlist, no `while True`, no recursion, no float
  `NaN`/`inf` literals without guards, no file/network access.
- Type check against the published `VesselState`/`Intent` interface.
- Every output path must be clamped to declared ranges — the envelope is
  the final backstop, but playbooks must show their own work.
- Result: `static_analysis.json` appended to evidence. Failure = terminal
  for this draft (Engineer revises).

### Stage 3 — REPLAYED (simulation gate, automated)

The draft runs against the **recorded-trip corpus**: black-box replays of
real past trips, including edge cases (rough sea, GPS dropout, shoaling).
Harness feeds historical state snapshots through `rules.py` and checks
`expectations.toml`:

- no intent outside declared envelope
- no oscillation (intent sign-flip frequency under threshold)
- sane behavior in sensor-gap windows (must hold or fail safe, never spike)
- comparison vs. what the human actually did (informational, not pass/fail)

The replay report is **sealed**: hash-recorded, immutable, cited by the
manifest. A playbook without a sealed replay report cannot advance.

### Stage 4 — APPROVED (human gate, mandatory)

The human sees a plain-language diff: what the boat will do differently,
in their vocabulary, with the replay evidence summarized. Approve or deny.
This is the one stage agents cannot cross alone. Denials feed back to the
Engineer as `human.escalation.answer` events with reasons — that signal is
training data.

### Stage 5 — SHADOW (live, non-actuating)

Playbook runs in the real control loop but its intents are **logged, not
executed**. Every tick: `agent.shadow.delta` event comparing playbook
intent vs. actual command. Graduation criteria (declared in manifest):
minimum hours, minimum agreement rate, zero envelope violations *had it
been active*. The Auditor certifies graduation.

### Stage 6 — ACTIVE

The kernel routes the control loop through this playbook. Continuous
monitoring: envelope rejections, watchdog misses, human overrides are all
attributed to the playbook's authority hash. Automatic demotion triggers:

- human veto rate above threshold → back to SHADOW
- anomaly detected by Auditor → immediate fallback to last-known-good
- sensor degradation below playbook's declared requirements → safe hold

### RETIRED

Kept forever. Content-addressed. Any retired playbook can be re-activated
via rollback in one command — its replay evidence travels with it.

## Replay as the universal test harness

Replay is not a playbook feature; it is the **system's** test harness
(axiiom A2). The same mechanism serves:

- **Playbook gate** (above)
- **Kernel regression:** every kernel change replays the corpus; identical
  inputs must produce verdict-compatible outputs
- **PID/tuning experiments** (legacy RQ-003): sweep gains offline against
  recorded sea states
- **Incident reconstruction:** feed the log back, watch what happened
- **Training:** humans and agents can both "drive" a recorded trip

Corpus management: the Analyst curates replay sets (`calm`, `rough`,
`gps_dropout`, `shoaling`, `engine_fault`), each a named slice of black-box
history with a manifest. New trips with novel conditions get promoted into
the corpus — the test suite grows by sailing.

## Versioning & storage

- Content-addressed: `playbook_id = hash(manifest + rules + provenance)`.
- The registry (in Memory, `docs/08`) maps `id → stage, evidence, stats`.
- Rollback is `boatctl playbook activate <id>` — no file copying, ever.
  The legacy timestamped-backup-file approach is dead.

## Contract summary for generated code

```python
# rules.py — GENERATED BY agent:engineer, sealed by stage-gate
# playbook: halibut_trolling_v3  hash: b3f9…  stage: ACTIVE

def evaluate_propulsion(state: VesselState, targets: Targets) -> ThrottleIntent:
    """
    Rule: ramp throttle before headwind turn to hold 2.3kn through the swing.
    Source: human.voice.transcript evt_01J3X… ("I always give her a bit before
    the turn or she falls off"), confidence 0.87, corroborated by 14
    telemetry-aligned instances (analyst finding f_221).
    Envelope: absolute adjustment ≤ 8%/tick, total range 10–40%.
    """
    ...
```

Functions that don't match this shape are rejected at Stage 2. The shape
is what lets a human read the boat's mind and lets another agent audit it.

## Anti-patterns (rejected at gate or by Auditor)

- Playbook calling another playbook (composition happens at mission layer)
- Hidden state (globals, files, clocks other than `state.timestamp_ms`)
- Adaptive self-modification at runtime — learning happens through the
  gate, never in the loop
- "Just this once" manual edits to `rules.py` on the boat — edits create a
  new draft, full stop
